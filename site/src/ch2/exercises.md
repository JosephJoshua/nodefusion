# 实现比较与练习

## 同一机制的两种组织方式

| 问题 | rCore | uCore |
| --- | --- | --- |
| 应用位置表 | `AppManager.app_start` | `app_info_ptr` 指向链接表 |
| 批次序号 | 启动前推进，表示下一应用 | 装载前推进，表示当前应用 |
| 用户上下文 | 内核栈顶的 `TrapContext` | 独立 `trap_page` 中的 `trapframe` |
| 入口取得上下文 | 交换 `sp` 和 `sscratch`，在栈上保存 | 交换 `a0` 和 `sscratch`，写入固定上下文 |
| write 成功返回值 | 输出长度 | 输出长度 |
| 不支持的描述符 | panic | 返回 -1 |
| 未知系统调用 | panic | 返回 -1 |
| 下一应用启动 | 新上下文交给 `__restore` | 新上下文交给 `usertrapret` / `userret` |

两套实现都清零并覆盖同一应用执行区域，都使用 `a7` 分发系统调用，都把普通调用的结果写入保存的 `a0`。上下文的存放位置决定了入口汇编如何取得它，也决定了它与调用栈的空间关系。

## 从寄存器追踪一次 write

在 [rCore 报告](../reports/rcore/ch2/2026a/rcore-2026A-ch2-reference.html)中找到第 11,648,879 条指令处的系统调用，再检查后续 `trap_handler` 与 `sys_write` 入口。

1. 用户 `a0` 的值为 1；为什么 `trap_handler` 入口的 `a0` 已经变成一个地址？
2. 用户请求写出多少字节？这个长度保存在上下文的哪个字段？
3. 处理函数更新的是硬件 CSR `sepc`，还是内存中的 `TrapContext.sepc`？最终由哪段汇编恢复到 CSR？
4. 若应用通过 `ecall` 请求退出，还会沿同一个上下文返回吗？

<details>
<summary>核对要点</summary>

入口汇编用 `a0` 传递上下文地址，原用户 `a0` 已保存在 `x[10]`。`a2 = 37` 对应保存的 `x[12]`。处理函数更新内存中的 `cx.sepc`，恢复汇编再将它写入 CSR。退出会建立下一应用的上下文。

</details>

## 检查异常是否推进批次

比较 rCore 的三次应用异常与 [uCore 修正版异常批次](../reports/ucoreos/ch2/2026a/ucore-2026A-ch2-faults.html)：

1. 找到向地址零写入的应用，区分日志文字与实际异常原因。
2. 将异常处理次数、系统调用次数与装载次数联系起来，解释最后一次装载检查。
3. 两个非法指令程序都产生原因 2。还需要哪些信息，才能区分执行 `sret` 和读取特权寄存器？

<details>
<summary>核对要点</summary>

向地址零写入产生原因 7。异常程序不必执行 exit，内核已经取得其执行控制权。七个应用需要八次下一应用检查，三个应用需要四次。区分两个非法指令程序可以结合装载顺序、异常地址、指令位模式和对应用户 ELF。

</details>

## 栈与保存区的空间关系

[uCore 原参考构建](../reports/ucoreos/ch2/2026a/ucore-2026A-ch2-reference.html)中，`trap_page` 的区间为 `[0x80219000, 0x8021a000)`，清零时 `sp = 0x80219f70`。

1. 将栈向低地址增长这一条件画在区间图上，标出当前 `sp` 与 `kernel_sp`。
2. 清零上下文页时，除了用户寄存器，还会改写哪些正在使用的数据？
3. 将 `kernel_sp` 修正为 `boot_stack_top` 后，为什么不能继续保留旧构建的地址表来解释新 ELF？
4. 如果仅把 `memset` 的长度缩短为 `sizeof(struct trapframe)`，是否已经建立了可靠的栈布局？

<details>
<summary>核对要点</summary>

函数调用使用的返回地址、保存寄存器与局部数据也落在该页内。缩短清零范围只能改变某次覆盖情况；栈仍与上下文页重叠，后续调用可能继续破坏保存的用户状态。应使两块存储不重叠，并用修正构建自身的 ELF 与记录重新核对。

</details>

## 补充缓冲区检查

两套 write 都直接使用用户地址。为本章增加检查时，可分别考虑描述符、区间溢出、允许读出的区域、UTF-8 和跨区间访问。

1. 给定 `ptr` 和 `len`，为什么先计算 `ptr + len` 再比较边界可能出错？
2. 用户代码区和用户栈不一定相邻。如何判断一个完整区间属于允许读取的区域？
3. 无效 UTF-8 是否等同于无效地址？按字节输出与按字符串输出各需要什么检查？
