# 实现比较与练习

## 文件操作与存储布局

| 问题 | rCore 第六章 | uCore 第六章 |
| --- | --- | --- |
| 文件对象怎样表示？ | `Arc<OSInode>`，保存偏移与权限 | 全局 `filepool` 中的 `file`，保存引用数、偏移与权限 |
| fork 后怎样使用文件？ | 复制文件对象的 `Arc` | 复制文件指针并增加 `ref` |
| 创建已有文件是否截断？ | `CREATE` 会截断 | `O_CREATE` 保留内容，`O_TRUNC` 截断 |
| 磁盘块大小 | 512 字节 | 1024 字节 |
| 磁盘索引节点大小 | 128 字节 | 64 字节 |
| 数据块索引 | 27 个直接地址、一级与二级间接地址 | 12 个直接地址、一级间接地址 |
| 目录项大小 | 32 字节 | 16 字节 |
| 块缓存容量 | 16 块 | 30 块 |
| 设备请求怎样完成？ | 驱动轮询 | 设备中断更新标志，发起者忙等该标志 |
| 用户程序在磁盘中的格式 | ELF | 平坦二进制文件 |
| 硬链接接口 | `fstat`、`linkat`、`unlinkat` 已实现 | 本提交中的这三个系统调用返回 `-1` |

两套实现都把一次打开的状态和磁盘文件身份分开保存。缓存容量、索引层数和请求完成路径则分别由各自的数据结构决定。

## 推演共享偏移

父进程两次打开同一个长度为 100 字节的文件，得到 `fd = 3` 和 `fd = 4`，随后调用 `fork`。所有打开对象的初始偏移为零。按下列顺序执行，每次读取均成功返回请求的字节数：

1. 父进程通过 fd 3 读取 5 字节。
2. 子进程通过 fd 3 读取 7 字节。
3. 父进程通过 fd 4 读取 2 字节。
4. 子进程通过 fd 4 读取 4 字节。

画出两个描述符表、两个文件对象和一个索引节点。标出每步之后两个偏移的值，以及这次读取覆盖的文件字节范围。再说明子进程关闭 fd 3 后，父进程还能否使用自己的 fd 3。

<details>
<summary>核对偏移与引用</summary>

两个偏移依次为 `(5, 0)`、`(12, 0)`、`(12, 2)`、`(12, 6)`。两次 open 形成的对象分别保存偏移，fork 后对应描述符共享原对象。四次读取的范围为 `[0, 5)`、`[5, 12)`、`[0, 2)` 和 `[2, 6)`。关闭子进程的 fd 3 释放一份引用，父进程仍持有该对象。

</details>

## 计算直接与间接索引

每个磁盘块地址占 4 字节。分别计算两套布局的直接地址容量、一级间接容量和整个文件的最大字节数，再找出下面的偏移使用哪个索引层：

| 实现 | 文件偏移 |
| --- | --- |
| rCore | 13,823、13,824、79,359、79,360 |
| uCore | 12,287、12,288、274,431 |

一个 3 字节请求从 rCore 文件的偏移 13,823 开始。它访问几个数据块？从直接索引切换到一级间接索引时，需要读取哪个额外的块？如果用户缓冲区也跨越 4096 字节页边界，分别说明用户内存和文件数据如何划分。

<details>
<summary>核对容量与边界</summary>

rCore 的直接容量为 `27 × 512 = 13,824` 字节，一级间接容量为 `128 × 512 = 65,536` 字节；两者合计 79,360 字节。加上二级间接索引后，总容量为 `16,539 × 512 = 8,467,968` 字节。uCore 的直接容量为 12,288 字节，最大容量为 `268 × 1024 = 274,432` 字节。

上述 rCore 请求访问逻辑块 26 和 27，第二个数据块地址来自一级间接索引块。用户缓冲区按页表映射拆分；文件读取按 512 字节块边界拆分。这两个边界可以落在请求中的不同位置。

</details>

## 截断与硬链接

在 rCore 中创建文件 A，写入一段内容，再为它建立名字 B。用两个独立的文件对象打开 A 和 B，检查 inode 编号、链接数与偏移。随后通过 A 截断文件，说明 B 读到的文件大小和两个对象的偏移怎样变化。

关闭这两个对象，再删除 A，检查 B 的内容与链接数。最后删除 B，沿 `clear_inode_data` 找到数据块、索引块和 inode 位图的回收位置。检查目录文件是否缩短，以及之后创建新文件如何复用空目录项。

uCore 的 `fileopen` 对已有文件分别使用 `O_CREATE` 和 `O_TRUNC`。比较两条路径对 `size`、块地址和打开对象 `off` 的修改，再查看 `iput` 中控制回收分支的条件。

1. 哪些目录查找或文件读取可以直接使用已有缓存？
2. `VirtIOBlock::read_block` 和 `VirtIOBlk::read_block` 为什么属于同一次设备请求？
3. 缓存命中后是否改变替换队列顺序？在缓存满时，哪个引用计数条件允许回收条目？
4. 写入文件后，哪些操作负责设置脏标志，哪些操作真正发出设备写请求？

再在 [uCore 报告](../reports/ucoreos/ch6/2026a/ucore-2026A-ch6-basic-observed.html)中查看 `bread`、`brelse` 与 `virtio_disk_rw`。说明缓存引用归零时为何移动链表节点，以及直接连续读取同一个块和重新装载另一块的路径有何区别。
