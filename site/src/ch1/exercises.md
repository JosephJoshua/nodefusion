# 实现比较与练习

## 相同的启动条件

| 问题 | rCore 第一章 | uCore 第一章 |
| --- | --- | --- |
| 汇编入口 | `_start` | `_entry` |
| 高级语言入口 | `rust_main` | `main` |
| 启动栈大小 | 64 KiB | 64 KiB |
| 清零函数 | `clear_bss` | `clean_bss` |
| 本次清零区间大小 | 4 KiB | 0 字节 |
| 字符输出 | SBI | SBI |
| 正常结束路径 | QEMU 测试设备成功退出 | `panic("ALL DONE")` 后 SBI 关机 |

两套入口都需要先建立栈。具体的 BSS 大小与终止路径随链接结果和实现选择不同，检查时应分别找到对应的边界与调用。

## 预测与验证

1. 如果删去入口中的 `la sp, boot_stack_top`，主函数的第一条栈写入可能使用什么地址？应在哪个入口检查 `sp`？
2. 将启动栈从 64 KiB 改为 32 KiB，哪些链接符号会移动？主函数入口的 `sp` 应如何变化？
3. 在 uCore 中增加一个实际被引用、初始值为零的静态数组，预测 BSS 边界与 `clean_bss` 的执行变化。若编译器消除了该数组，如何从 ELF 中发现？
4. 日志过滤改变后，函数轨迹与串口输出可能出现哪些差异？
5. 若清零函数已进入，但快照中数据仍非零，分别检查循环边界、观察时刻与后续写入。

<details>
<summary>思考题提示</summary>

第二题中，栈底取决于前面各段的长度，栈顶取决于栈底和预留大小。BSS 起点排在栈顶之后，两者通常一起移动。

第三题需要同时检查编译后的符号、BSS 边界和清零函数的分支。已被优化掉的源级数组不会形成预期的内存区域。

第五题中，清零入口只说明函数开始执行；快照可能发生在循环结束之前，也可能发生在其他初始化代码重新写入之后。

## 检查一个启动实现

完成课程接口后，依次检查入口地址、栈的有效范围、清零区间、输出接口和结束路径。入口地址与链接位置应一致；清零范围应排除当前启动栈；主函数的第一条函数调用应使用有效栈指针。

第一章建立了内核自身的执行环境。第二章将加入用户程序装载与特权级切换，需要为用户执行另行准备栈、入口和异常返回状态。
