# 实现比较与练习

## 进程资源的归属

| 问题 | rCore 第五章 | uCore 第五章 |
| --- | --- | --- |
| 控制块怎样存储？ | 动态分配，由 `Arc` 管理 | 静态进程表 |
| 父子关系怎样表示？ | 父持有子 `Arc`，子用 `Weak` 指向父 | 子进程保存父控制块指针 |
| fork 怎样取得用户内存？ | 按区域建立映射并复制数据页 | 按有效低地址 PTE 复制数据页 |
| 内核栈怎样取得？ | 分配动态页和栈编号 | 使用表项对应的静态数组 |
| exec 后根页表是否保留？ | 新 `MemorySet` 替换旧地址空间 | 保留根页表，替换低地址映射 |
| 子进程未退出时怎样等待？ | 内核返回 `-2`，用户库让出后重试 | 内核重新入队、切换并继续扫描 |
| 数据页何时释放？ | 退出时 | 退出时 |
| 页表页何时释放？ | 等待移除最后一个强引用时 | 退出时 |
| 父进程先退出怎样处理？ | 子进程交给 `INITPROC` | 子进程父指针清空，已退出的表项回收 |
| 就绪进程怎样选择？ | 选择最小 stride | 按队列顺序取出 |

两套实现都通过复制用户状态建立子进程，再分别维护内核执行上下文。回收时机的差异来自各自的数据结构和所有权安排。

## 从同一次 fork 继续执行

设父进程中变量 `value` 的值为 7。调用 `fork` 后，子进程将它改成 9，父进程保持原值。

1. 父子进程保存的用户 PC 应指向哪条指令？如果复制时仍指向 `ecall`，子进程首次运行会发生什么？
2. 两个进程中 `value` 的虚拟地址是否相同？找到各自 PTE 后，怎样检查它们使用独立物理页？
3. 哪些内核地址可以保持相同？分别检查共享跳板、异常上下文页和内核栈。

<details>
<summary>核对执行状态</summary>

两者从 `ecall` 的下一条指令继续，保存的 `a0` 分别为子进程 PID 和零。变量的虚拟地址相同，数据页的物理页号不同。跳板代码共用物理存储；异常上下文和内核执行状态分别保存。复制后仍指向 `ecall` 会使子进程再次执行系统调用。

</details>

## 手工执行调度选择

两个 rCore 进程 A、B 的初始 stride 都为零，优先级分别为 4、8，就绪队列顺序为 A、B。每次选中的进程运行后立即让出，并回到队尾。

写出前六次选择的进程、选择后的 stride 和队列顺序。随后将 A 的优先级改为 8，保留已有 stride，再执行两次选择。最后将优先级设为 65537，检查整数除法后的增量。

<details>
<summary>核对前六次选择</summary>

增量分别为 16384 和 8192。前六次为 A、B、B、A、B、B，之后两者的 stride 都为 32768。修改优先级不会清零已经累计的值；大于 65536 的优先级得到零增量。

</details>

## 跟随一次创建与等待

在 [rCore 基础测试报告](../reports/rcore/ch5/2026a/rcore-2026A-ch5-basic-observed-v2.html)中找到指令计数 `26,710,023` 的 `proc.fork`。核对父 PID 0、子 PID 1，再找到 `26,767,015` 的 `proc.exec`。

1. `exec` 属于哪个进程？这个操作是否产生新的 PID？
2. 打开邻近快照，找到 PID 0 和 PID 1。查看两者的用户页表、内核栈和状态，并列出共享与独立的资源。
3. 找到测试程序退出后的 `KernelStack::drop`。当前执行进程与被回收子进程的 PID 是否相同？根据 `waitpid` 中的引用释放解释这次调用。

在 [uCore 基础测试报告](../reports/ucoreos/ch5/2026a/ucore-2026A-ch5-observed.html)中，第一次 fork 位于 `413,158,400`，父 PID 1、子 PID 2。父进程在 `413,158,902` 进入 `wait`，子进程在 `413,316,173` 进入 `exit`。

1. 按 PID 筛选并比较这三个事件的先后顺序。父进程第一次进入等待时，子进程处于哪个阶段？
2. 搜索函数 `wait` 和 `sched`。恢复父进程时，返回到用户态还是继续执行内核中的扫描循环？
3. 沿子进程的 `freeproc` 查看用户页和页表的释放，再与成功等待时的表项状态变化对照。

<details>
<summary>核对创建与等待</summary>

rCore 的第一次 fork 由初始用户进程创建 shell，`exec` 属于 PID 1。PID 0 与调度器 idle 上下文分别保存执行状态。等待者移除子进程的最后一个强引用时，子进程资源在等待者的内核执行路径中释放。

uCore 的父进程在子进程退出前进入 `wait`。它重新入队并切回调度器；再次被选中后，沿保存的内核上下文返回 `sched`，继续扫描子进程。用户页和页表已在子进程退出路径释放。

</details>

## 核对物理页计数

rCore 基础测试记录 1,365 次分配、1,259 次归还；扩展测试记录 1,469 次分配、1,363 次归还。两次结束时分配器使用页数均为 106。uCore 记录 606 次分配、539 次归还，结束时为 67 页。

分别计算分配与归还的差，核对录制结束时的计数。再解释 rCore 扩展测试的峰值为何高于基础测试。可以结合 `spawn`、同时就绪的进程数和各自的地址空间提出假设，再用创建事件和内存快照检查。

在 rCore 扩展报告中，`sys_waitpid` 的完整入口计数为 8,903。说明为什么这个值不能直接表示回收了 8,903 个子进程，并找出用户库重试等待的条件。
