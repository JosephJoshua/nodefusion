# 实现比较与练习

## 地址空间的组织方式

| 问题 | rCore 第四章 | uCore 第四章 |
| --- | --- | --- |
| 应用怎样装载？ | 解析 ELF，为各段分配数据页 | 直接映射嵌入内核的二进制 |
| 用户代码权限怎样确定？ | 按各 ELF 段设置 | 装载区统一 `RWXU` |
| 用户栈权限是什么？ | `RWU` | `RWXU` |
| 页表页由谁管理？ | `PageTable.frames` 中的 `FrameTracker` | 调用方通过 `freewalk` 回收 |
| 数据页由谁管理？ | `MapArea.data_frames` | 调用方及 `uvmunmap` 的 `do_free` 参数 |
| 用户地址转换怎样检查？ | `translate_user` 检查 `V/U` 和请求权限 | `walkaddr` 检查 `V/U` |
| 撤销映射以什么为单位？ | `munmap` 匹配整个 `Framed` 区域 | `uvmunmap` 处理指定页数 |
| 任务退出是否回收地址空间？ | 控制块仍持有 `MemorySet` | `freeproc` 未调用 `uvmfree` |

两套内核都使用三级页表、独立用户页表和共享跳板。区域组织、权限设置与回收责任的差异，可以沿装载、访问和撤销三个过程对照阅读。

## 计算地址转换

1. 将 `0x4123` 分解为三级页表索引与页内偏移。如果数据页起始地址为 `0x87fb9000`，物理字节地址是多少？
2. 地址改成 `0x5123` 后，哪一级索引改变？原来的两个中间页表是否还能复用？
3. 两个用户页表将同一个虚拟页映射到不同物理页时，页内偏移是否改变？切换任务时，处理器如何知道使用哪张页表？

<details>
<summary>核对计算</summary>

`0x4123` 的索引为 `0、0、4`，偏移为 `0x123`，物理地址为 `0x87fb9123`。`0x5123` 的末级索引变成 5，前两级索引保持不变，因而可以共用同一条中间页表路径。页内偏移取自访问地址；根页表由当前 `satp` 指定。

## 沿一次请求阅读源码

在 rCore 中，从 `sys_mmap` 开始找到数据页分配和末级项写入的位置。再从 `sys_munmap` 开始找到区域匹配、页表项清零和 `FrameTracker` 析构的位置。

假设映射区间为 `[0x4000, 0x6000)`，分别预测撤销 `[0x4000, 0x5000)` 和撤销整个区间的结果。将预测与 `remove_framed_area` 的匹配条件对照。

在 uCore 中，对同一个数据页依次执行 `do_free = 0` 和 `do_free = 1` 的撤销操作。写出两次调用之后页表项、空闲链表和数据页内容的变化。第二次撤销之前，需要先重建映射。

## 用运行报告核对

打开 uCore [页表实验](../reports/ucoreos/ch4/2026a/ucore-2026A-ch4-pagetable.html)，定位到第 413,037,577 条累计指令处的撤销入口。

1. 找出参数中的虚拟地址、页数和 `do_free`。RISC-V 调用约定中，它们分别位于哪些参数寄存器？
2. 查找第二次撤销后的物理页归还记录，将地址与最初映射参数对照。
3. 为什么撤销跳板时使用 `do_free = 0`？为什么 `freewalk` 之前必须移除跳板的末级项？

打开 rCore [运行报告](../reports/rcore/ch4/2026a/rcore-2026A-ch4-observed.html)，比较区域撤销与单页撤销计数。一个区域可以包含多页，缩小堆也可以触发单页撤销，因此两类入口计数的含义不同。

## 修改实验

在独立页表实验中，将数据页权限改成只读用户页。分别检查页表中的 `W` 位、`walkaddr` 的返回结果，以及用户态真正执行写指令时的异常。说明软件查找函数和硬件访问检查各自执行了哪些判断。

再将测试字节移到下一页的起始地址之前，让一次缓冲区复制跨越两个虚拟页。把两页映射到不连续的物理页，检查复制函数如何保留虚拟连续缓冲区的顺序。
